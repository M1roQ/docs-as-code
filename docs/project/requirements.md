# Требования

## User Stories

### US-01. Отправка отзыва

Как пользователь,
я хочу отправить текст отзыва,
чтобы узнать его тональность.

Критерии приёмки:

- пользователь может ввести текст отзыва;
- система принимает отправленный текст;
- после отправки пользователь видит, что отзыв обработан.

### US-02. Определение тональности отзыва

Как пользователь,
я хочу автоматически определять тональность отзыва,
чтобы быстро понять, положительный, нейтральный или отрицательный это отзыв.

Критерии приёмки:

- система передаёт текст отзыва ML-модели;
- ML-модель возвращает одну из категорий: положительная, нейтральная или отрицательная;
- пользователь видит определённую тональность отзыва.

### US-03. Просмотр результата классификации

Как пользователь,
я хочу видеть результат классификации и уровень уверенности модели,
чтобы понимать, насколько надёжно определена тональность отзыва.

Критерии приёмки:

- после обработки система отображает определённую тональность;
- система отображает уровень уверенности модели;
- если классификация невозможна, пользователь получает сообщение об ошибке.

## Use Case

### UC-01. Определение тональности отзыва

**Актор:** пользователь

**Цель:** определить тональность отправленного отзыва.

**Предусловие:** пользователь ввёл текст отзыва и отправил его в систему.

**Основной сценарий:**

1. Пользователь вводит текст отзыва.
2. Пользователь отправляет отзыв на обработку.
3. Система передаёт текст отзыва ML-модели.
4. ML-модель определяет тональность отзыва: положительная, нейтральная или отрицательная.
5. Система получает результат классификации.
6. Система отображает пользователю определённую тональность отзыва.

**Альтернативный сценарий:**

Если ML-модель не может обработать текст отзыва или не может определить тональность,
система сообщает пользователю об ошибке и предлагает повторить попытку позже.

**Результат:** пользователь видит определённую тональность отзыва или получает сообщение о невозможности классификации.
